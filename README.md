# Bybit Monitor Bot

Мониторинг цен и объёмов Bybit + Telegram-алерты.
Стратегия — «уровневый отбой», см. [`docs/STRATEGY.md`](docs/STRATEGY.md).

## Возможности

- **WebSocket-push** цен (`tickers.{symbol}`) — без REST-поллинга.
- **REST-fallback** при `USE_WEBSOCKET=false`.
- Пошаговый диалог добавления алерта: тикер → цена → направление → заметка.
- Кнопки у алерта: «📝 Взять в дневник», «📊 Выгрузить данные»
  (CSV по 15m/1H/4H/1D), «🗑 Удалить».
- Антиспам: кулдаун на повторные срабатывания (`data/cooldowns.json`).
- Анализ: RSI, EMA, ATR, HTF-тренд, паттерны, касания уровня.
- **План сделки в алерте:** Entry / SL / TP1 / TP2 / RR / size + hard filters.
- **Сканер уровней:** автоскан 4H/1D и добавление найденных уровней
  одной кнопкой (см. ниже).
- **Дневник разворотов:** статистика отрабатываемости сетапов прямо
  в тексте алерта.
- **Виртуальные сделки:** симуляция входа/SL/TP с частичными TP —
  без реальных ордеров.
- Ретраи Telegram и кулдаун при сбоях: алерт не теряется, а
  помечается `telegram_error`.
- Нормализация тикеров: `sol` → `SOLUSDT` (через `resolve_symbol`).

### Стратегия «Уровневый отбой»

Алерт — это не просто «цена пересекла уровень», а полноценный **план
сделки** по стратегии:

- **Entry / SL / TP1 / TP2** — с расчётом от структуры и уровней 4H/1D.
- **RR** — по TP1 и TP2, с проверкой hard filter `RR ≥ 1:3`.
- **Size** — размер позиции под риск ≤ 1% от депозита.
- **Runway** — запас хода до TP1 ≥ 2×ATR.

Плюс валидация по стратегии:

- **RSI-дивергенция** (бычья/медвежья) на локальных пивотах.
  Для `direction='any'` возвращаются **обе**, как индикатор.
- **Структура тренда 4H** — HH/HL (восходящий), LH/LL (нисходящий).
- **Уровни 4H/1D** — с зеркальностью и фильтром износа.
- **Изношенный уровень** (`touches >= 5`) — hard_filter `worn_level`.
- **Зона вместо линии** — алерт можно ставить на диапазон (`64000-66500`).
- **Поглощение** — строгое (тело ≥ 1.5× предыдущего, тень ≤ 0.5 тела)
  даёт полный вес паттерна, слабое — половину.

**Порог доставки и вердикт — разные вещи.** Вердикт в сообщении — метка:
`💪 Strong` (score ≥ 5.5), `⚠️ Weak` (≥ 3.5), `🟡 Marginal` (≥ 2.5),
`❌ None` (< 2.5). В Telegram уходит всё, что получило вердикт кроме
`❌ None` и прошло hard filters, то есть score ≥ **2.5**. Ручной порог
сверху — кнопка `⚙️ Порог алертов` (`alert_min_score`, по умолчанию
`-inf` = не резать дополнительно).

**Один ATR на сделку:** `atr_1h`, при отсутствии — `atr_15m`. SL — от
структуры ± `ATR_MULTIPLIER × atr`, а TP1/TP2 — следующие сильные
уровни 4H/1D (не N × ATR). Нет TP1 → сетап отклоняется (`no_target`);
нет TP2 → RR считается по TP1.

### Сканер уровней

Кнопка `📊 Сканер уровней` в главном меню: бот сам находит уровни на
4H/1D (свинги → кластеризация → касания → score) и предлагает их
добавить.

- **`▶️ Запустить сейчас`** — разовый скан.
- **`🔔 Автоскан`** — по расписанию, по умолчанию `6,18` UTC.
- **`🎯 Порог score`** — минимальный score уровня для показа
  (по умолчанию `5.0`).
- **`⏰ Часы UTC`** — пресеты расписания или свои значения.

Значения хранятся в `data/settings.json` рядом с остальными
runtime-настройками.

Результат: «➕ SYMBOL · N уровней» (добавить все уровни символа),
«➕ ➕ Добавить все уровни», «📋 Все уровни текстом» (по одной кнопке
на уровень) и «🔄 Обновить». Уже добавленные уровни не дублируются.

### Дневник разворотов

Кнопка `📈 Статистика разворотов`: бот записывает исход каждого
**отправленного** алерта и считает, насколько часто отрабатывает
похожий сетап.

- `success` — ход в сторону алерта ≥ `1.0 × ATR_1h` за 8 свечей 15m;
  `fail` — раньше пробита стоп-зона `level ± 0.5 × ATR_1h`;
  `expired` — за 48 ч исхода не было (в процент не идёт).
- В алерте появляется строка
  `📈 История: pinbar·vol≥2x·wick·htf+·RSI<40 → 65% (n=24)`,
  когда записей по сетапу ≥ `REVERSAL_MIN_N_DISPLAY` (по умолчанию 15).
- Меню: запись ВКЛ/ВЫКЛ, минимальное n для показа, статистика, экспорт
  CSV, очистка дневника.

Дневник **не влияет** на score и hard-фильтры — это только информация
для принятия решения.

### Виртуальные сделки

Кнопка `💼 Виртуальные сделки`: симуляция сделок по алертам, без
реальных ордеров. Бот **не торгует**.

- Под алертом — кнопка `📝 Взять в дневник`: создаёт виртуальную
  сделку из плана (entry / SL / TP1 / TP2).
- Статусы: `pending_entry` → `open` → `closed` / `cancelled`.
- Поддержаны **частичные TP** (`50/50` или `33/33/34`); PnL считается
  по закрытым порциям, риск и плечо — метаданные.
- Меню: активные сделки, история, статистика, экспорт CSV, отмена.
- Хранение — `data/virtual_trades.jsonl`.

### Настройки (runtime)

Команда `/settings` (или кнопка `⚙️ Настройки` в меню) —
изменение без перезапуска бота:

- **`⚙️ Порог алертов`** — минимальный score для отправки.
  Пресеты: `ВСЕ (-∞)`, `≥ -5`, `≥ 0`, `≥ 3` + свой. Значение `-∞` —
  слать всё, `≥ 3` — только железобетонные.
- **`⛔ Hard-filter алерты`** — слать ли алерты с непройденным
  hard filter (с плашкой ⛔). По умолчанию **`ВЫКЛ`**: такие алерты
  только пишутся в историю. `ВКЛ` — режим наблюдения (на свой риск).
- **`📜 Глубина истории`** — сколько последних алертов хранить
  (пресеты 1000 / 5000 / 10000 / 50000 + свой). По умолчанию 10000.

Это все пункты `/settings`. Настройки сканера уровней, дневника
разворотов и виртуальных сделок живут в их собственных меню
(`📊 Сканер уровней`, `📈 Статистика разворотов`,
`💼 Виртуальные сделки`) и в `.env`.

Настройки сохраняются в `data/settings.json` и переживают перезапуск.

### Массовое добавление алертов

Одна строка формата:

```
SYMBOL PRICE DIR [ОПИСАНИЕ]
```

Вместо одной цены можно задать **зону**:

```
SYMBOL LOW-HIGH DIR [ОПИСАНИЕ]
```

Где:
- **SYMBOL** — `BTC`, `btc`, `BTCUSDT`, `btcusdt` — нормализуется в
  `BTCUSDT`. Только USDT-пары (USDC / BTC-квоты → пропуск).
- **PRICE** — число > 0. **LOW-HIGH** — диапазон (`64000-66500`,
  можно длинным тире `64000–66500`), границы нормализуются сами.
- **DIR** — `up | down | any | long | short | вверх | вниз`.
- **ОПИСАНИЕ** — всё, что после `direction`, **как есть** (включая
  `|`, `#`, `Вход:`, `Стоп:`). Сохраняется в `setup_note`.

Примеры:
BTC 65000 up пробой хая
ETHUSDT 3200 down ретест | Стоп: 3400 | Тейк: 2900
aaVe 180.5 down ретест сопротивления
BTC 64000-66500 up зона набора

Алерт с зоной срабатывает при **входе цены в диапазон**: для `down` — при
пробое верхней границы сверху, для `up` — нижней снизу, для `any` — любой.
Если добавить новую зону, пересекающуюся с существующей (то же направление),
она заменит её; «касание» границами тоже считается пересечением.

Многострочный ввод — обрабатывается как пакет, с отчётом
`✅ Добавлено: N, ❌ Пропущено: M` и указанием причин.

### История алертов (для отладки)

Кнопка `📜 История алертов` в главном меню — выгрузка CSV с **всеми**
сработавшими алертами (включая отфильтрованные), с полями:

- **`strategy_pass`** — прошёл ли сетап по стратегии;
- **`was_sent`** / **`skip_reason`** — ушёл ли в Telegram и почему нет;
- **`pattern_score`** / **`pattern_reason`** — что решил анализатор;
- **`pattern_strict`** — строгое ли было поглощение (`null` для пин-баров);
- **сырые свечи** (`candle`, `prev_candle`, `candle_ts`).

Полезно для оффлайн-анализа: понять, правильно ли фильтры отсортировали
сигналы, не отрезаем ли что-то полезное.

Разобрать файл можно скриптом (без сети, только чтение):

```bash
python scripts/analyze_history.py                 # отчёт по умолчанию
python scripts/analyze_history.py --last 500      # последние 500 записей
python scripts/analyze_history.py --symbol BTCUSDT
python scripts/analyze_history.py --json          # машинный вывод
```

Отчёт показывает: сколько отправлено/отброшено, распределение вердиктов и
score, причины пропуска (`skip_reason`), hard filters, паттерны (включая
долю строгих поглощений), статистику объёма и топ символов.

**Дедупликация:** одна запись на `(symbol, level, direction, candle_ts)`,
отправленные алерты не затираются последующими пропусками.

## Требования

- Python 3.12+
- Telegram-бот (токен от [@BotFather](https://t.me/BotFather))
- Доступ к публичному API Bybit v5 (ключи не нужны — только public endpoints)

## Установка

```bash
git clone <repo-url>
cd bybit-monitor-bot
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
```

## Настройка

```bash
cp .env.example .env           # Windows: copy .env.example .env
```

Заполните в `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
- `TELEGRAM_CHAT_ID` — ваш chat_id (узнать у @userinfobot);
- `EQUITY` — депозит в USDT для расчёта размера позиции.

По умолчанию `SEND_INVALID_ALERTS=false`: в Telegram уходят только сетапы,
прошедшие hard filters. Для отладки можно поставить `true` — тогда
алерты «не по стратегии» тоже будут приходить (с плашкой ⛔).

## Запуск

```bash
python main.py
```

Остановка — `Ctrl+C`. Данные (`alerts.json`, история, кулдауны) лежат в `data/`.

## Тесты

```bash
pytest -q                                # 620 тестов, без сети
ruff check src tests main.py scripts
pytest -q --cov=src --cov-report=term    # покрытие (pytest-cov)
```

## Структура

```
main.py                          — точка входа: бот + монитор + планировщики
src/api/                         — REST и WebSocket клиенты Bybit
src/core/                        — алерты, анализ, риск, уровни,
                                   дневник разворотов, виртуальные сделки
src/parsers/                     — массовое добавление (SYMBOL PRICE|LOW-HIGH DIR)
src/telegram/                    — бот, хендлеры, клавиатуры
src/utils/                       — конфиг, индикаторы, форматирование
scripts/                         — analyze_history.py: разбор истории алертов
tests/                           — pytest, без сетевых вызовов
data/                            — alerts.json, история, кулдауны, дневники
```

Документация: [`docs/STRATEGY.md`](docs/STRATEGY.md) — стратегия и
правила, [`docs/REFACTORING.md`](docs/REFACTORING.md) — история
этапов, текущий техдолг и дорожная карта.

## Что бот НЕ делает

Не торгует. Никаких ордеров, ключи Bybit не нужны — только публичные
эндпоинты. «Виртуальные сделки» — симуляция на бумаге для проверки
стратегии (см. [`docs/STRATEGY.md`](docs/STRATEGY.md), §6).
